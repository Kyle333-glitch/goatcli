# GOAT v0.4.0 — Verified Update Acceptance Matrix

This matrix records the acceptance criteria for the `goatcli` verified update system introduced in v0.4.0.

## Legend

- **Status**
  - ✅ Implemented and verified locally
  - ️ Implemented, awaiting CI/native evidence
  - 🔶 Partially implemented / requires follow-up
  - ❌ Missing / blocked

## 1. Trust and Metadata Authentication

| ID | Criterion | Status | Evidence |
|----|-----------|--------|----------|
| T1 | Embedded TUF root is pinned at build time and hash-verified before use. | ✅ | `src/update/policy.ts:compiledVerifiedUpdatePolicy`, `src/update/trust.ts:TufTrustStore` constructor |
| T2 | Root metadata rotation is sequential, monotonic, and re-verified. | ✅ | `src/update/trust.ts:applySequentialRoots`, `trust.test.ts:modifiedCanonicalManifestFailsSignature` |
| T3 | Timestamp, snapshot, targets, and channel metadata are signed according to TUF thresholds. | ✅ | `src/update/trust.ts:TufTrustStore.authenticateInternal`, `trust.test.ts:real TUF thresholds authenticate one consistent channel metadata set` |
| T4 | Revocations are monotonic and inherited across updates. | ✅ | `src/update/trust.ts:assertRevocationsMonotonic`, `trust.test.ts:revocation lists cannot be rolled back` |
| T5 | Expired metadata is rejected for new updates; installed receipts remain re-authenticable without expiry enforcement. | ✅ | `src/update/trust.ts:TufTrustStore.authenticate` vs `TufTrustStore.authenticateInstalledReceipt` |
| T6 | Metadata version/digest floors prevent rollback/replay. | ✅ | `src/update/trust.ts:assertMetadataFloors`, `trust.test.ts:same-version metadata bytes cannot be replaced` |
